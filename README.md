# 🀄 麻将AI助手 (Mahjong AI Assistant)

实时麻将辅助决策系统:通过"看"真实牌桌,重建完整牌局状态,**推断三家对手的隐藏手牌与听牌威胁**,并给出牌效最优的出牌建议。

> 只读辅助 — 不操作游戏、不注入、不修改游戏进程。

## 核心功能

- 🎯 **实时牌桌理解** — 截屏 → 检测/跟踪/识别 → 四家牌河 + 副露 + 手牌,抽象为毫秒级事件流
- 🔮 **对手隐藏手牌推断** — 粒子滤波实时估计三家手牌,输出听牌概率 / 最可能等待牌 / 放铳率
- 💡 **出牌推荐** — 向听数优先 + 有效进张枚数,附推荐理由("打出 9饼 后 1 向听, 有效进张 28 枚")
- 🛡️ **放铳预警** — 候选牌三家放铳率实时显示,高危险牌标红
- 🖥️ **自适应面板** — 三档布局(窄条/牌桌/宽屏)+ 降级链,任意窗口尺寸不挤不溢出
- 📊 **离线评估** — 合成对局模拟器 + 真值对比,量化验证推断能力

## 它解决什么问题

从游戏界面里,要回答三个问题——而每一个都比看起来难:

1. **"桌上有哪些牌?"** — 实时视频检测中,漏检、误检、帧间抖动是常态(牌面小、动画遮挡、低帧率)——任何单帧检测都不可能完美。直接把每帧检测当真相,状态机几分钟就崩。
2. **"这张牌是谁打的?"** — 固定区域划分在线上看似可行,但真实牌局里四家牌河在画面中央交错、物理不可分(上家牌河延伸到我的牌河上方);更本质的是,固定区域方案绑定 UI 坐标,无法迁移到线下实体麻将。只有"出牌轮转 + 落点身份跟踪"的时间方案,同时解决线上交错,又天然适配线下。
3. **"对手手里有什么?"** — 永远看不到。只能从"他打了什么、没打什么"反推——一个信息不完备的贝叶斯推断问题。

**核心思路:不把检测当真相,把不可靠的视觉信号抽象成事件流,再用时间约束做全局解码。**

## 核心设计决策

**① 两级识别:检测器低阈值召回,分类器高精度过滤**

整体 recall 74% 看似够用,但分区域看差异很大:手牌(大目标)recall 高,牌河(15px 小目标)recall 明显更低——而牌河才是信息的主战场(四家的出牌历史都在这里)。把检测阈值调低能找回漏检的牌河牌(recall → 85%),但低阈值会带进来大量误检(UI 元素、牌面残影),precision 掉到不可用。

所以在同一张图上跑**两级模型**:检测器(yolov8m)低阈值全图找框(高召回),ROI 分类器(yolov8n-cls)对每个框裁剪放大 2 倍做特写分类(98.3%)——误检框被分类器的"背景类"直接滤掉。召回与精度同时拿到,而不是在同一个模型上调阈值做零和取舍。

> 效果:牌河 recall ~85% @ precision 98%(低阈值召回 + 分类器过滤)。

**② 从像素到归属:事件流 + 时间约束解码**

实时视频检测的漏检/误检/抖动不可避免(牌面小、动画遮挡、低帧率)。系统的第一原则:**检测输出不是真相,而是候选信号**。从检测到"谁打了什么",分两层消化错误:

- **事件生成层**:把连续帧抽象成事件(牌出现 / 牌河消失 / 手牌数台阶 / 副露信号),每类事件要求**多信号交叉确认**才成立(例如"消失"必须同河其他牌还在才计数)——单帧错误最多造成一次事件延迟,不污染全局状态;
- **归属解码层**:四家牌河在画面中央交错、物理不可分,固定区域方案又绑定 UI 坐标无法迁移线下——用**行动者轮转**(谁出牌轮到谁)做全局强先验 + ByteTrack 身份跟踪 + beam search 联合解码"谁打了什么";证据不足时保留不确定(软归属),新证据到达时用快照回放精确修正历史,而不是推翻重来。

> 效果:真实对局中手牌检测塌陷时事件流不中断、被碰/漏检不产生连锁错位。

**③ 对手手牌是不可观测量的贝叶斯推断**

对手手牌永远看不到,只能从"他打了什么、没打什么"反推。用**粒子滤波**(3 家 × 400 粒子)近似后验分布;关键在观测模型——理性玩家不会打出毁牌效的牌,用"向听数边际价值"建模打出似然;归属不确定时按概率部分更新粒子,而不是赌一个答案。

> 效果:能认出对手手牌约 95% 的成分(随机猜只有 11%);"对手在听牌"的判断与实际相符(说 6 成就是真的约 6 成);对手真听牌时,猜中他听什么牌约三到五成。

**④ 实时性:推理不阻塞主循环**

游戏进行中,检测/推断全部放后台线程,主循环只做轻量事件处理。

> 效果:主循环零卡顿,摸牌到显示延迟 ~1 秒。

## 系统架构

一条流水线,五层处理(编号对应上面"核心设计决策"):

```
游戏画面
  │  截屏(后台线程, 最新帧优先)
  ▼
① 视觉识别   YOLO 检测 + ByteTrack 跟踪 + ROI 特写分类
  │  输出: 每帧 ~60 个牌面框(牌面 / 位置 / 身份)
  ▼
② 事件提取   牌出现 / 牌河消失 / 手牌数变化 / 副露信号
  │  输出: 可靠事件流(多信号交叉确认, 容忍单帧错误)
  ▼
③ 归属解码   行动者轮转 + beam search(软归属 + 冻结 + 翻案)
  │  输出: 每一张牌属于哪一家
  ▼
④ 对手推断   粒子滤波 × 3 家(牌效似然 + 软观测)
  │  输出: 听牌概率 / 等待牌 / 放铳率
  ▼
⑤ 出牌推荐   向听数 + 有效进张(副露展开评估)
  │  输出: 推荐牌 + 理由 + 危险牌预警
  ▼
   自适应 UI 面板(手牌 / 四家牌河 / 副露 / 威胁 / 推荐)
```

## 量化验证

自建合成对局模拟器,真值全程已知,离线对比推断结果(10 局 × 400 粒子):

| 指标 | 结果 | 大白话 |
|---|---|---|
| 认出对手手牌 | **约 95%** | 随机猜只能认出 11% — 系统接近"开挂视角" |
| 听牌判断可信度 | 数值不虚 | 说对手"有 6 成在听牌",十次里真的大约六次在听 |
| 猜中听什么牌 | 3-5 成 | 对手真听牌时,猜中他听的牌(前三名候选)的概率 |
| 出牌推荐对比 | 更接近听牌 | 新算法推荐的牌,整局平均向听数更低(和旧算法 A/B 对比) |

评估入口: `uv run python scripts/eval_inference.py`

## 目录结构

```

src/mahjong_ai/inference/ 粒子滤波对手建模(软观测、快照回放、副露扣池)

scripts/               运行入口、评估、数据标注/训练链
tests/                 359 个测试(单测 + 合成对局端到端回归)
```

## 快速开始

```bash
uv sync                # 安装依赖(含 GPU 版 torch)
uv run pytest          # 359 个测试
uv run mypy src        # 类型检查
uv run ruff check src tests scripts
```

运行实时辅助(需欢乐麻将 PC 客户端已开启):

```bash
uv run python scripts/run_assistant.py
```

> 模型权重与训练数据不在本仓库(`data/` 已排除)。目录约定:
> `data/models/screen/mahjong_screen_detector/weights/best.pt`(检测器)、
> `data/models/roi_cls/weights/best.pt`(ROI 分类器)。
> 首次运行按提示用 `pick_regions.py`(8 区域框选)完成桌面标定。

## 训练自己的模型

系统使用两级识别:检测器(yolov8m)找牌框 → ROI 分类器(yolov8n-cls)精修牌面类别。两条训练链:

**屏幕检测器**:

```bash
uv run python scripts/capture_dataset.py --frames 2000   # 1. 采集游戏截图
uv run python scripts/label_review.py                    # 2. 人工审核打标
uv run python scripts/build_dataset_yaml.py              # 3. 拆分 train/val + data.yaml
uv run python scripts/train_screen_yolo.py               # 4. 训练检测器
```

**ROI 牌面分类器**(检测框裁剪 → 放大特写分类):

```bash
uv run python scripts/build_roi_dataset.py   # 1. 从检测框裁剪构建数据集(含背景类)
uv run python scripts/train_roi_cls.py       # 2. 训练分类器
```

输出自动同步到 `data/models/` 固定路径,重启 `run_assistant.py` 即生效。

## 未来规划

- **检测精度重训**: 数据闭环(采集/标注/训练链)已就绪, 将检测 recall 从 74% 提升至 90%+
- **真实对局验证**: 结算核对工具已建, 积累真实对局统计, 用真值校准推断(而非仅合成模拟)
- **四家联合推断**: 三家对手独立建模 → 全局一致性推断(共享牌池/副露互相约束)
- **摸牌预测**: 从"未知槽"升级为摸牌分布预测(结合剩余牌墙与各家牌效)
- **线下场景迁移**: 桌面游戏 → 线下实体麻将(事件驱动记录, 不依赖特定 UI)
- **最终愿景**: 一个通用的"看牌"引擎 — 输入任意牌桌画面, 输出完整对局理解(手牌/威胁/推荐), 可嵌入教学、复盘、观战场景
