# 麻将AI助手 v3 设计方案 — 以目标为导向的重构

日期: 2026-08-12
状态: 设计稿(待评审)
范围: 线上欢乐麻将 PC 客户端(只读辅助), 大众麻将 144 张带花, 35 类

---

## 1. 目标与约束

### 1.1 目标(按优先级)

1. **对手手牌推断**(核心创意): 出牌策略观测模型 — 谁打了什么 → 推断听牌/放铳
2. **我的牌效辅助**: 出牌推荐/听牌提示(可靠性优先, 只依赖我的手牌)
3. 实时运行(欢乐麻将对局中), 后续迁移线下([[offline-design]])

### 1.2 关键认识

> 四家牌河归属不是目标, 是推断的输入。
> 推断接受"概率化"的输入 — 归属做到 85% 概率正确 + 软观测, 与 95% 硬归属
> 对推断的最终影响几乎相同, 而复杂度差一个数量级。

### 1.3 约束

- 只读辅助(不操作游戏), 实时 15fps 主循环
- 检测模型 yolov8m@1280(现状 hand P96/R96, river P96/R68)
- 桌面静态画面 + 间歇动作(打出/碰/杠/摸牌动画)

## 2. 现状问题(重构动机)

| # | 问题 | 根源 | 代价 |
|---|---|---|---|
| 1 | 硬归属链条长(轮转/校准/观察期/回溯/副露转移), 每环都可能错且无纠错 | 追求"完美归属" | 复杂度爆炸, 脆弱 |
| 2 | 手牌检测是唯一锚点, 漏检 → 轮转漂移无兜底 | 手牌 13→14 转变校准 | 根基风险 |
| 3 | 2 帧确认/观察期/TTL/max_age 断裂补丁, 一半复杂度为漏检服务 | river recall 68% | 治标 |
| 4 | 推断观测模型弱(听牌早期 ~0), 归属再准也白搭 | P2 未做 | 投入产出倒挂 |
| 5 | 状态机每帧全量处理, 事件耦合难测 | 演进积累 | 调试成本高 |

## 3. 架构总览

```
┌─────────────────────────────────────────────────────┐
│  ① 检测层    YOLO m@1280(重训提 recall)            │
│  ② 跟踪层    ByteTrack 官方跟踪(track_id 身份)     │
│  ③ 事件层    事件提取: 新ID/ID消失/副露/手牌变化    │
│  ④ 状态层    回合状态机(强约束) + 各家持久状态      │
│  ⑤ 推断层    软观测粒子滤波(归属概率化输入)         │
└─────────────────────────────────────────────────────┘
   实时闭环: ①→②→③→④→⑤(轻量)
   离线复盘: 完整日志 → 离线精确重放(无实时约束)
```

设计原则:
1. **事件流水线替代每帧状态机** — 每类事件独立可测
2. **回合强约束显式建模** — 冲突即纠错
3. **软归属替代硬归属** — 推断接受概率, 不追求完美
4. **检测优先治本** — 提升 recall, 砍掉补丁
5. **实时/离线分层** — 实时轻量够用, 离线精确

## 4. 详细设计

### 4.1 检测层(治本)

目标: river recall 68% → ≥85%(precision 保持 ≥95%)

- 数据集: 已做 remerge(模型预测合并进 label, 覆盖 3.1 万框) — 上家牌河等漏标已补齐
- 重训: yolov8m@1280, 标定验收: river P≥95% @ R≥85%
- 多尺度推理可选: 牌河小框(15px)是 recall 短板, 训练时增强小目标/降采样增强
- 验收脚本: analyze_threshold / analyze_fp(test_real 50 张同局序列)

**recall 提升后, 以下补丁可以删除**: 2 帧延迟确认、观察期 TTL、部分多确认空间兜底
(新牌出现 ≈ 真实打出, 事件即真)

### 4.2 跟踪层(保留现状)

- ScreenVision.track(): model.track(persist=True, bytetrack) 逐帧连续
- track_id = 牌的身份(跨帧稳定, 实验: 同位置 ID 保持 98.9%, 隔帧漏检恢复 85-100%)
- 保留 TileDet.track_id 字段与解析

### 4.3 事件层(新): 事件提取

从每帧检测结果提取**事件**, 流水线处理:

```
事件类型:
  NEW_ID(track_id, tile, x, y, conf)    # 新目标出现(潜在新打出)
  ID_GONE(track_id)                     # 目标消失(漏检/释放, 软信息)
  MELD_GROUP(boxes, cx, cy)             # 紧凑组(碰/杠/吃候选)
  HAND_CHANGE(hand_count)               # 我的手牌数变化(去抖后)
```

提取规则:
- NEW_ID: 本帧 track_id 不在上一帧 ID 集合 → 候选事件
- MELD_GROUP: cluster_dets 的 melds 输出(现成)
- HAND_CHANGE: 手牌去抖输出变化(现成)

事件带帧号/时间戳, 进入队列。**事件处理是纯函数(输入事件+状态, 输出状态+输出事件)**, 单测容易。

### 4.4 状态层: 回合状态机(强约束)

```
状态: actor(当前行动者) + round_played{player: bool}(本轮已打)
轮转表: [my → right(下家) → top(对家) → left(上家)]  (用户确认)

事件处理规则(核心):
  NEW_ID 确认后:
    ① actor 本轮未打 → 归属 actor, round_played[actor]=True
    ② actor 本轮已打(冲突!) → 冲突检测:
       本轮内 actor 不可能再打(规则强约束) → 回退: 按空间概率归属
       (锚点距离 → 概率, 见 4.5)
    ③ 轮转推进: actor = 轮转表下一位(该轮打牌数 ≤ 1/人 校验)
  MELD_GROUP 确认后:
    归属(贴手牌=我 / 锚点概率) → 行动者转移给副露家(碰/杠截断轮转)
  HAND_CHANGE:
    手牌 13→14 → 校准 actor = my(回合锚定, 与现状同)
    手牌 14→13 → 我打出一张(若本帧有 NEW_ID 归属我则闭环)

冲突检测 = 纠错机制(现状没有):
  "某家本轮已打却又出现归属它的新牌" → 概率上本轮归属必错
  → 修正: 该事件改为软归属(4.5), 不回写硬身份
```

开局处理(替代观察期/回溯):
- 校准前: NEW_ID 只累积(事件暂存), 不归属
- 校准(第一次 13→14): 暂存按轮转逆序回溯分配(与现状同, 已验证)

### 4.5 软归属(核心变化): 概率观测

硬归属 → **归属概率分布**:

```
新牌 P(玩家i) ∝ w_space(i) × w_turn(i)
  w_space(i) = 归一化 1/(1 + dist(落点, 锚点i))     # 空间证据
  w_turn(i)  = 轮转相位先验(actor 及相邻位的权重)    # 时间证据
```

- 确定性高时(单锚显著近 / 轮转相位清晰)→ 概率 ≈ 1 → 等价硬归属
- 交错区/冲突时 → 概率摊开 → 粒子滤波按软观测更新(不犯错, 只降低确信度)

输出: `Event{player_dist: {my: .7, right: .2, ...}, tile, ts}`

**推断层输入从"谁打了什么"变成"谁以多大概率打了什么"** — 观测模型接口不变
(observe_discard), 内部按概率加权。

### 4.6 推断层(观测模型升级, P2 补全)

- 软观测接入: 粒子滤波 observe_discard 按 player_dist 加权
- 观测模型升级: 出牌策略(向听数/牌效)观测 — 让听牌概率早期有区分度
  (现状: 随机先验 ~1%, 打几张牌后仍无区分)
- 放铳率: 维持现状(候选牌 × 各家听牌概率)

### 4.7 实时/离线分层

```
实时(欢乐麻将对局中):
  流水线 ①→⑤ 轻量闭环
  输出: 我的出牌推荐(高可靠) + 别家听牌粗估(软观测, 概率化)
  容错: 任何一环失败 → 降级(该帧丢弃/该事件跳过), 不崩主循环

离线复盘(对局后):
  完整日志(帧级 trace + 截图/检测记录) → 离线重放
  无实时约束: 可做精确归属(回溯修正)+ 完整推断
  产出: 对局报告(各家真实牌河/听牌/放铳对比结算) — 简历展示物
```

离线重放与实时共用事件流水线(同一代码路径), 只差"实时源 vs 日志源"。

```
  run_assistant.py     实时源(帧 → 事件流水线)
```

核心接口:

```python
# 事件流水线(纯函数, 单测)
```

## 6. 实施计划(2026-08-13 修订: 按目标重排优先级)

**原则: 停止输入管道的边际优化, 把精力投到推断与验证。**

| 阶段 | 内容 | 验收 | 状态 |
|---|---|---|---|
| P0 冻结检测 | 当前模型为基准(river P99%/R70% + ROI 精修), 停止数据/训练迭代 | A/B 选定基准模型 | 进行中 |
| P1 观测升级 | 向听数/牌效观测模型(核心招牌) | 模拟对局: 观测 5-10 张后听牌概率有区分度 | **下一优先** |
| P2 真实验证 | 5+ 局 trace + settle_check 对比 | 归属链循环率; 推断 vs 结算 | 依赖 P1 |
| P3 离线复盘 | replay_game: 日志重放 + 对局报告 | 结算核对闭环 | 依赖 P2 |
| P4(可选) 事件化重构 | tracker → 事件流水线 + 软归属 + 冲突检测 | 现有测试迁移通过 | 仅当真实对局暴露硬归属问题时再做 |

理由(2026-08-13 复盘):
- 检测迭代边际收益递减: recall 68.5→70.3→66.8(重训反降), 多轮投入无净收益;
  70% recall + 时间归属已覆盖多数打出事件, 粒子滤波对漏检天然鲁棒
- ROI 精修已验证足够(类别错 280→11), 剩余纯误检/漏检不影响推断量级
- 推断观测模型弱才是真瓶颈(听牌概率早期全 ~1%), 归属精度 85% vs 95%
  对最终推断几乎无差别
- 硬归属链条(观察期/回溯/延迟确认/轮转)已工作, 事件化重构是锦上添花,
  不是瓶颈 — 仅在真实对局暴露问题时再做

## 7. 验证与验收

- 单元: 事件流水线纯函数(事件→状态 转换表); 回合冲突场景单测
- 回放: test_real 50 帧同局序列(事件流水线全链路)
- 真实: 5 局 trace(归属链 我→右→上→左 循环率 ≥95%; 开局回溯分配正确)
- 结算: settle_check(推断 vs 实际胡牌/听牌对比)
- 性能: 实时主循环 ≤66ms/tick(跟踪已异步, 事件处理微秒级)
