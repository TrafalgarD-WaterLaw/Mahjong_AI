# 麻将AI助手 v2 设计文档: 线上实操 + 对手推断 + 线下迁移

- **日期**: 2026-08-05
- **状态**: 已批准(用户确认)
- **范围**: 麻将AI项目整体方向规划(v2)
- **依赖**: mahjong_core / mahjong_engine / mahjong_ai / mahjong_cv (Phase 1-2 已有代码)

## 概述

把现有「拍照识别手牌」的单机原型升级为「**通用麻将辅助决策系统**」:先在腾讯欢乐麻将 PC 客户端上实操(只读辅助,截屏识别 → AI 分析 → 悬浮窗 HUD 提示),再逐步迁移到线下真实麻将。核心创意点是**对手手牌推断**:通过三家出牌序列与副露,用粒子滤波推断其手牌组成、听牌概率与最可能胡牌,并据此给出带放铳率的出牌建议。

最终形态是一个可写进简历的完整项目:多采集源(屏幕/摄像头)+ 多视觉方案(屏幕YOLO/实物YOLO)+ 多规则集 + 概率对手推断 + 实时 HUD + 录像复盘验证闭环。

## 需求确认

| 维度 | 决定 |
|------|------|
| 形态 | 只读辅助,不注入操作、不自动打牌 |
| 玩法 | 欢乐麻将「推倒胡」模式(136张,允许吃;复用陕西引擎 + 局部调整) |
| 平台 | 欢乐麻将 PC 客户端(Win32 窗口捕获) |
| 展示 | 无边框置顶悬浮窗 HUD |
| 节奏 | 3-6 个月,质量优先,完整版 |
| 决策 | 出牌推荐升级为「牌效 × 放铳率」权衡,支持弃和 |

## 设计决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 架构 | 五层可替换管线(采集/视觉/状态/决策/展示) | 线上→线下只换前两层,决策层零改动 |
| 线上识别 | 训练专属 YOLO 屏幕牌检测模型 | 数据管线自动化打标,CV 简历含量高;实物模型视觉域不匹配,不可复用 |
| 数据标注 | 截屏 + 模板匹配自动打标 → YOLO 格式数据集 | 屏幕牌为固定 2D 图标,模板匹配可作为自动标注教师 |
| 基础模型 | YOLOv8n(与实物模型同代,统一技术栈) | 轻量实时;YOLO26n 作为同数据集 A/B 备选 |
| 对手推断 | 分层:硬约束排除 + 粒子滤波(出牌策略观测模型) | 精确贝叶斯枚举不可行(C(122,13)≈10¹⁷);朴素采样不利用打牌逻辑 |
| 放铳率 | 粒子集合占比统计 | 框架自然产物,无需额外设计 |
| 验证 | 结算亮牌 vs 系统推断,自动核对 | 欢乐麻将结算展示胡牌手牌,天然 ground truth,零人工标注 |
| 规则调整 | 陕西推倒胡 → 欢乐推倒胡:允许吃牌等 | 局部改动,不动 IRuleSet 架构 |

## 1. 总体架构

```
┌─ 采集层 CaptureAdapter ─────────┐
│  Win32CaptureAdapter  ← P1 (欢乐麻将PC窗口, 10-30fps)  │
│  CameraCaptureAdapter ← P3 (USB摄像头)                 │
├─ 视觉层 VisionEngine ───────────┤
│  ScreenVision  ← P1-2 (YOLO26 屏幕牌检测,本项目训练)    │
│  TableVision   ← P3   (实物牌检测,现有 best.pt 体系迭代) │
├─ 状态层 GameStateTracker ───────┤  (共享)
│  手牌/牌河(三家,含序数)/副露/碰杠胡提示/回合归属,帧去抖   │
├─ 决策层 DecisionCore ───────────┤  (共享,复用现有代码)
│  mahjong_engine: 欢乐推倒胡规则集(含吃牌)               │
│  mahjong_ai: 出牌推荐(牌效×放铳)、碰杠胡建议            │
│  mahjong_ai/opponent: 对手推断(硬约束+粒子滤波)         │
└─ 展示层 Presenter ──────────────┘
   HudOverlayPresenter (PySide6 无边框置顶悬浮窗)
```

接口契约:每层定义 adapter 接口,线上→线下仅替换「采集层 + 视觉层」实现。

## 2. 阶段路线图

| 阶段 | 内容 | 周期 | 里程碑 |
|------|------|------|--------|
| P1 线上闭环 | 窗口捕获 → 数据管线(自动打标)→ 训练 YOLO26 屏幕模型 → 状态机 → 欢乐推倒胡规则调整 → HUD | 4-6 周 | 打一局欢乐麻将全程自动提示 ✅ 已完成 |
| P2 对手推断与风险决策 | 牌河逐张识别 → 粒子滤波推断器 → 放铳率 → 弃和推荐 → HUD 预警 → 结算核对;识别鲁棒性;录像复盘 | 4-8 周 | 可复盘每手牌失误,推断准确率曲线 |
| P3 线下迁移 | 摄像头采集、实物 YOLO 管线迭代、透视/遮挡/光照鲁棒性、场景管线完善、ONNX 提速 | 8-12 周 | 线下麻将桌旁实时提示 |
| P4 收尾 | 打包安装、文档、演示视频、CI、README | 2-4 周 | 简历可展示成品 |

**P1 关键路径**:数据管线闭环(截屏→自动标注→训练→验证)必须第 2 周内跑通,否则后续全部卡住。

## 3. 数据管线(P1 关键路径)

1. 固定欢乐麻将窗口尺寸与缩放(简化标注与检测)
2. 从截图中**手工/半自动**抠出 34 种牌模板(一次性)
3. 自动采集:多局、多阶段、多家牌河截屏
4. 模板匹配(基于窗口坐标的网格扫描 + 模板相似度)→ 自动生成 YOLO 格式 labels
5. 数据增强:窗口缩放、位置偏移、亮度/对比度扰动、动画中间帧采样
6. 基于 `yolo26n.pt` 微调训练 → 屏幕牌检测模型
7. 人工抽检验证集准确率,达标后进入推理

目标:首版数据集 ≥ 5000 张图 / 牌实例 ≥ 20 万,模型 mAP@0.5 ≥ 0.95(2D 图标任务可达到)。

## 4. 对手推断模块(`mahjong_ai/opponent`,P2 核心)

### 输入观测(全部来自视觉识别)

- 每家出牌序列(牌河,含序数)
- 每家副露(吃/碰/杠,明示搭子)
- 剩余牌计数(我的手牌 + 全部可见牌)
- 回合数/局数(阶段先验)

### 分层推断架构

```
┌ 硬约束层 (每帧) ─────────────────────────────┐
│  排除法: 出过的牌 → 不在手牌                   │
│  副露 → 必然包含该搭子                         │
│  缺门/断门推断,向听数上界估计                   │
├ 软推理层 (每秒) ─────────────────────────────┤
│  粒子滤波,每家 N=500 粒子                      │
│  每粒子 = 一副与所有观测一致的 13 张候选手牌      │
│  新观测(出牌/副露)→ 按观测模型权重重采样         │
│  观测模型 P(出 t | 手牌 H) = 出牌策略:          │
│    基于向听数 + 牌效(孤张/搭子价值)+ 拆搭逻辑     │
├ 输出 ──────────────────────────────────────┤
│  每家的向听数分布 / 听牌概率 / 最可能听的牌(1-3张) │
│  放铳率(x) = 该家粒子中「手牌+x 成胡」的占比     │
│  安全牌集合(他家出过/低放铳率)                   │
└────────────────────────────────────────────┘
```

### 可选进阶(不阻塞主线)

- 全局联合 MCMC:三家手牌 + 牌墙整体采样,张数全局守恒,精度增强
- P3 学习型预测:用结算核对积累的对局数据训练小模型直接预测听牌分布,与粒子滤波集成

### 验证闭环

结算界面亮胡牌玩家手牌 → 复盘时自动核对「系统当时推断的听牌 vs 实际胡牌」→ 生成推断准确率 vs 牌局阶段曲线 → 数据沉淀供 P3 学习型模型使用。

## 5. 决策升级(P2)

- 出牌推荐:候选牌打分 = 牌效推进(向听/期望进张)− 放铳风险(各家放铳率加权)
- 某家听牌概率 > 阈值时,优先推荐安全牌,支持**弃和**
- 碰/杠/胡建议保持现有优先级(胡 > 杠 > 碰 > 过),杠/碰决策同样纳入放铳视角
- 决策日志记录:时刻、局面、候选评分、实际选择,供复盘

## 6. 展示层 HUD(PySide6)

- 无边框、置顶、半透明,吸附游戏窗口位置
- 我的手牌建议:推荐出牌高亮 + 理由 + 备选(放铳率标红)
- 对手区域:听牌概率条 + 最可能胡牌 1-3 张
- 碰杠胡提示:别家打出牌时标注可执行操作
- 危险牌预警:将要打出的候选牌标红放铳率

## 7. 错误处理与鲁棒性

- 帧丢失/识别置信度低 → 状态保持上一有效帧,不猜测
- 动画中间帧/特效遮挡 → 置信度阈值 + 时序去抖(连续 N 帧一致才提交状态)
- 窗口尺寸变化/遮挡 → 重新校准区域映射
- 识别与规则矛盾(如检测出 5 张同牌)→ 仲裁:以副露/合法张数为准
- 全链路失败降级:识别失败时仅显示「检测中」,不输出误导建议

## 8. 测试策略

- 单元测试:规则调整(吃牌)、粒子滤波更新/重采样、放铳率计算、安全牌集合
- 快照测试:录制固定帧序列 → 识别/状态/推断输出基线对比(防回归)
- 集成测试:`demo.py` 链路扩展,合成画面(程序生成牌面)→ 端到端断言
- 实测验证:真机打局,结算核对推断准确率
- 质量门禁沿用:pytest + mypy strict + ruff

## 9. 非目标(YAGNI)

- 全自动打牌/操作注入(明确排除,风险与定位不符)
- 读内存/抓协议获取状态(排除)
- 多玩法引擎扩展(四川/广东等)(仅保留 IRuleSet 扩展点,不实现)
- 手机端 app / 模拟器适配(PC 客户端优先,采集层 adapter 留好接口)
- 在线对战平台数据抓取

## 10. 里程碑产物(简历呈现)
