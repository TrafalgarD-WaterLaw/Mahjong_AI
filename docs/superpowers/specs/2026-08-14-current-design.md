# 麻将AI助手 当前方案(2026-08-14 重组)

状态: **现行实现**(以代码为准; v3 设计稿中未实施部分见 §10)
范围: 腾讯欢乐麻将 PC 客户端(只读辅助), 大众麻将 144 张(花牌合并为 1 类), 35 类

---

## 1. 一句话方案

截屏 → YOLO 检测 + ByteTrack 身份跟踪 → ROI 分类精修 → DBSCAN 聚类(手牌/副露/牌河)→ 状态机归属(**时间为主: 行动者轮转 + 跟踪身份; 空间为辅: 用户框选区域权威纠错**)→ 粒子滤波对手推断 + 牌效出牌推荐 → 双显示层(悬浮框 + 独立客户端)。

四家牌河归属是推断的输入, 不是目标。归属不需要完美 — 粒子滤波对少数错位天然鲁棒。

## 2. 全链路(实时闭环)

```
捕获 Win32Capture, 主循环 66ms ≈15fps
  ├─ 画面区域检测(每 ~30 帧): 去黑边 → 框选区域重映射(窗口缩放自适应)
  ├─ 后台推理线程(最新帧优先, 忙时丢旧帧; imgsz=960)
  │    ScreenVision.track(): YOLO conf=0.15 → ByteTrack → ROI 精修 → 双重合并
  ├─ GameStateTracker.update(): DBSCAN 聚类 → 手牌去抖 / 副露确认 / 牌河归属
  ├─ AssistantSession.tick(): 粒子滤波观测 → 十判(后台线程)→ 推荐 + 放铳率
  ├─ 显示: DetOverlay(游戏上悬浮框, 可关) + MahjongClient(独立小窗, 绝不覆盖游戏)
  └─ 日志: hand(手牌变化) / infer(每 10 帧推断快照) / trace(帧级, --trace)
```

原则: 单帧异常只记录不崩溃; 任何一环失败降级, 不杀主循环。

## 3. 视觉层(检测 + 跟踪 + 精修)

| 环节 | 方案 | 关键参数 |
|---|---|---|
| 检测 | YOLO 屏幕模型(class id = 牌编码 0-34) | conf 0.15(低阈值召回), imgsz 960(实时)/1280(标定) |
| 跟踪 | 官方 ByteTrack, track_id = 牌的身份 | `bytetrack_mahjong.yaml`: high 0.35 / low 0.05 / new 0.15 / buffer 120(8 秒) |
| 精修 | 每框 crop(±4px)→ 96×96 → yolov8n-cls 36 类覆盖类别 | 类别错 280→11; **背景类(35)输出 → 丢弃框**(误检过滤) |
| 合并 | 同类重叠框去重(精修前后各一次) | IoU > 0.35 只留高 conf |

设计依据: 检测器 recall 74% 是硬上限 → 低阈值召回 + 背景类兜底误检; 类别混淆靠放大特写解决(98.3%); 漏检由 ByteTrack 长 buffer 兜底(8 秒内重现仍是旧 ID, 不触发假事件)。

## 4. 状态层 — 归属机制(核心)

`GameStateTracker` 每帧: 聚类 → 归属 → 提交快照。所有推断只读快照, 不读瞬时检测。

### 4.1 聚类(DBSCAN 特征分类)

- 局部 eps = 2.0 × min(两框宽)(透视补偿: 近大远小), min_samples=1
- **手牌**: count≥3 + 水平线性 + cy 最大 + 尺寸锚(均高 ≥ 0.75×全局)
- **副露**: 2-4 张 + packing≥1.0(框面积和/bbox, 紧贴无空隙)+ 均高 ≥ 0.7×手牌(透视补偿, 不限位置 — 自己/别家都识别)
- **牌河**: 其余全部(含单张)

### 4.2 手牌

去抖: conf≥0.55, 滑动窗口 5 帧 majority 3, 上限 14, 按牌面位置排序(与显示一致)。

### 4.3 行动者模型(时间归属的引擎)

```
轮转表: 我 → 右(下家) → 上(对家) → 左(上家)   [用户确认]

校准(只认转变, 防 stale-14 锁死):
  手牌 13→14 转变 → actor = 我(我刚摸牌)
帧末推进:
  手牌 14→13 且 actor=我 → actor = 下家(我打完了)
单确认推进(仅单确认帧, 双确认是动画/快照不推进):
  归我的牌且 actor=我 → 下家; 归别家 → 轮转下一位
副露转移: 确认副露 → actor = 副露家(碰/杠截断轮转, 该家接着打)
```

### 4.4 牌河归属决策链(新牌河 ID 出现时)

**第 0 层 — 硬过滤(根本不进归属)**:
- 花牌(tile 34): 摸到即亮出放角落, 不是打出
- 手牌带内(±10px): 手牌碎片物理上不可能在牌河
- 无 track_id / conf < 0.30 且无已有身份(已有身份的牌低 conf 帧也收)

**第 1 层 — 副露补全吸收**: 新 ID 紧贴已确认副露(< 0.5×框宽间隙)= 漏检的第 3/4 张亮牌 → 吸收, 永不进牌河。

**第 2 层 — 空间权威**: 落点在框选牌河区域内 → 直接归该家(固定 UI 区, 碾压行动者/锚点)。

**第 3 层 — 锚点强证据纠错**(区域外落点): 行动者锚距 > 1.5× 空间锚距, 或落点距空间锚 < 10% 短边 → 按空间归属。

**第 4 层 — 时间归属(默认)**: 归首现帧行动者。新 ID 连续 2 帧确认(误检 TTL 15 帧); 首现帧行动者回溯 3 帧(ByteTrack 轨迹确认延迟 ~3 帧 — 迟到检测不能用"现在"的行动者)。

**归属后**:
- 跨帧类别投票: 同 ID 最近 5 帧类别众数(消除七万↔九万闪变)
- 锚点自学习: 该家锚点向落点 EMA 微调(lr 0.05, 点选不准自动修正)
- 多 ID 同帧确认(动画间隔)→ 空间归属(轮转语义不明)
- 牌河事件 = 张数差分(同牌第 2 张也触发, 牌池不漏扣)

### 4.5 开局生命周期(庄家未知也精确)

```
基线:     无 ID 映射且未校准 → 空间归属建 ID→玩家映射, 入序列不触发事件
观察期:   校准前新 ID 只暂存, 不归属不事件
校准:     第一次 13→14(我摸牌) → 暂存按轮转逆序回溯分配(最后一张=我上一位打出)
          副露确认也解除观察期(副露局手牌可能永远不到 13)
```

### 4.6 副露(碰/杠/吃)

- 归属: ① 框选副露区域(权威) ② 与手牌同行 = 自己 ③ 最近锚点
- 确认: 候选池按位置匹配(±40px), 累计 3 帧确认(防短暂误检); 确认后不回退(漏检只是没看见)
- 手牌联动: 我的碰/吃 -2, 杠 -3
- 行动者转移给副露家

## 5. 推断层(对手建模 + 我的建议)

```
出牌/副露事件(增量) → 粒子滤波 ×3 家(400 粒子)
  ├─ 观测: observe_discard(粒子过滤/重采样) + observe_public(三家扣牌池)
  ├─ 先验: 结构化采样(相邻牌/对子倾向) + β=0.4 向听漂移
  └─ 十判: 后台线程(0.17s/家, 事件触发 dirty, 自动合并), 双版本缓存

我的建议(不依赖归属):
  ├─ 出牌推荐: 牌效引擎(向听数 + 孤张价值分层); 手牌 2 张起都推荐(相对判断)
  ├─ 副露后: 混入(n≥13) exclude 副露牌 / 剔除(n<13) melds 展开合并评估
  ├─ 听牌提示: 手牌 13 张(或 13-3k+副露展开=13)
  ├─ 放铳率: 候选牌(推荐+备选)每 3 帧刷新, ≥15% 提示弃和+安全候选
  └─ 操作建议: 别家打牌事件 + 手牌 13-3k ±2 容错 → 碰/杠/吃建议
```

## 6. 显示层 — 可见与推断拆分

```
悬浮框 DetOverlay(游戏上): tracker._boxes 归属框(手牌绿/副露蓝/四家牌河按家着色)
客户端 MahjongClient(独立窗, 响应式 430×600 不遮挡游戏):
  牌河显示 = _visible_tiles(p) = 当前物理可见框(_boxes)
    → 被碰走的牌从显示消失(它已不在牌河)
  推断 = players[p].river(打出历史事实, 永久保留)
    → 被碰走的牌仍作为听牌/牌池依据
  副露徽章: 碰·X / 杠·X
```

## 8. 验证闭环

```
对局记录: run_assistant --trace → data/settle_logs/game_*.jsonl
  hand(手牌变化) / infer(每10帧: 四家牌河+副露+听牌概率+放铳率) / trace(帧级归属明细)
分析: analyze_game.py — ① 归属链循环率(新牌序列 vs 轮转期望, 含副露转移)
  ② 四家牌河分布 ③ 副露明细 ④ 转移重锚 ⑤ 可疑冲突(连续同家)
结算核对: settle_check.py — 终局推断 vs 结算亮牌(听牌/top3 命中/校准桶), 多局累计 stats
```
