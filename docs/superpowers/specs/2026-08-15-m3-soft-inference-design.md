## 1. 目标

1. **对手推断实时化**: 归属软分布即时喂粒子滤波(不等冻结), 三家听牌概率/最可能听牌/放铳率在打出后 ~1 秒内更新
2. **翻案精确修正**: 8 秒窗口内归属翻案时, 粒子状态回退重放 — 用户选择"即时观测+翻案反向修正"(方案 A: 观测日志 + 快照回放)
3. **副露局补全**: 我的推荐/听牌在副露局(手牌 13-3k)正常工作; 吃后听牌提示
4. 复用: OpponentInference 粒子算法(内部加软观测入口)、session.InferenceResult 数据类、客户端渲染(零改动)、settle_check

## 2. 需求澄清结论(用户确认)

| 决策点 | 结论 |

| 范围 | 推断 + 副露局推荐/听牌 + 放铳率显示 全做 |

## 3. 模块与数据流

```
主循环(runner._handle, 零阻塞):
  ① 解码器照旧 → 新事件/新冻结
  ② 新观测: TileAppeared 事件到达即推 (obs_id, tile, 当前归一化分布)
     并记录"观测时 MAP"(翻案比对用)
  ③ 翻案: 冻结事件 player ≠ 观测时 MAP → observer.correct(obs_id, 冻结分布)
  ④ 副露: MeldFormed → 推扣池观测(§5 张数规则); TileClaimed 决定 claimed 情形
  ⑤ 读缓存: 三家听牌概率/最可能听牌/放铳率 → Advice.inference
  ⑥ 我的推荐/听牌: 副露局判定(§6)
  ⑦ 跨局: consume_new_game → observer.reset

SoftObserver(后台线程, 新文件 src/mahjong_ai/inference/soft_observer.py):
  push(obs) / correct(obs_id, dist) / reset(...) → 队列
  worker: 快照 → 应用 → 批量十判(0.5s 节流) → 写缓存
  读: cached_inference() → session.InferenceResult
  同步模式(worker=False): 单测直接 apply_all()
```

原则:
- 旧 session/tracker 不碰;SoftObserver 是 inference 包内新文件,复用 OpponentInference
- 客户端零改动(听%/放铳行/边框着色走同一 Advice.inference 通道)
- 观测日志含翻案审计记录 — 复盘资产

## 4. SoftObserver 内部(核心机制)

**软更新(观测 (obs_id, tile, dist) 到达)**:
```
① 快照四家(粒子表 + 牌池 + RNG 状态 + hand_count) — 每事件 ~0.4ms
② 每家按权重 w=dist[p] 做"部分粒子更新":
   k = round(w×400) 个粒子走 observe_discarded(反向过滤: 粒子 = 打出后
   手牌, 不含刚打出的 tile; 似然 = 从"粒子+tile"的打出前手牌打出该牌
   的牌效似然), 其余 400−k 原样 — 统计上 = 贝叶斯混合
③ 观测入全局日志(时间序)

注意(2026-08-16 校准修复): 打出观测一律反向过滤, 不再区分是否副露。
听牌家打掉的多是刚摸进的牌 — 正向过滤(要求粒子含该牌)会把真听牌手
结构性滤掉, 评估实测模型概率 27/42 挤在 0-0.2 桶而实际听牌 48%;
全员反向过滤后: 手牌质量 0.59 → 0.95, waiting top3 命中 14-22% → 33-55%,
分桶校准单调且各桶实际值均落在预测区间内(400 粒子)。
```

**翻案纠正(correct(obs_id, 新分布))**:
```
回退四家到 obs_id 的快照 → 从 obs_id 起按新分布重放之后全部观测
→ 重算十判缓存。确定性(RNG 状态在快照里), 结果 = 从头按新分布算
```

**快照剪枝**: 事件冻结后其快照可丢,只保留窗口内(≤12 份)。触发方 = runner:每次观察到新冻结的 eid,调用 observer.prune(frozen_eids) — 剪掉"最后一个未冻结 obs 之前"的快照。

**粒子权重下限**: dist[p] < 0.05 的玩家跳过(k=0 — 低置信不喂粒子)。

## 5. 副露扣池张数规则

```
pong(t,t,t): 被碰的那张已随打出事件扣过(observe_public) → 再扣 2(碰家手牌)
秒碰(claimed=None): 打出事件从未发生 → 扣 3
chi(a,b,c): 扣非 claimed 的两张(claim 事件指定被吃的那张)
明杠(claimed 有): 扣 3; 暗杠(claimed 无): 扣 4
碰家 hand_count: 碰/吃 −2, 杠 −3(MAP 碰家)
```

## 6. 我的推荐/听牌(副露局, 平移 session.tick 既有逻辑)

```
k = 我的副露组数; n = 去抖手牌张数
n ≥ 13(副露混入手牌检测): 副露 tile 全排除出候选
n < 13(副露已被聚类剔除): 手牌全可打, melds 展开合并补足 14 张评估
听牌提示: 手牌 + 副露展开 = 13 → get_waiting_tiles(吃后 10+3=13 → "你已听牌")
放铳率候选: 推荐牌 + 备选前 5(变化即重算, 否则每 3 帧)
```

## 7. 测试与验收

- SoftObserver 单测(同步模式):
  1. w=1.0 单家观测 == 旧硬观测行为
  2. w=0.25 → 恰好 100 粒子被更新
  3. 快照回放确定性: [A,B] 应用后回退重放 == 从头重放
  4. 翻案修正等价性: 先 {A:0.9} 后纠正 {B:0.9} == 直接 {B:0.9}
  5. 副露扣池张数: pong 2 / 秒碰 3 / chi 2 / 明杠 3 / 暗杠 4
  6. 跨局 reset 牌池语义
- 集成: 合成事件流(复用 synth.py 剧本)+ 真值 → 听牌概率区分度回归(听牌家 vs 散牌家, 沿用旧 5 倍区分验收线)
- 真实对局: 听% ~1 秒内更新、放铳行、副露局听牌提示、settle_check(任务 #48)

## 8. 性能

```
每事件(后台): 快照 0.4ms + 部分粒子更新 100-300ms
十判: 队列清空后批量重算, 最小间隔 0.5s(三家 ≈0.5s)
主循环: 只入队/读缓存 — 零阻塞
滞后: 打出 → 听%变化 ≈ 0.5-1.5 秒(已确认)
内存: 快照 ≤12 份 × 4 家 × 400 粒子, 可忽略
```

## 9. 风险

| 风险 | 缓解 |
|---|---|
| 部分粒子更新的统计偏差(k 取整) | round 取整, 权重下限 0.05; 单测 ② 钉住 |
| 快照回放与 RNG 状态耦合 | RNG getstate/setstate 入快照; 单测 ③④ 钉住确定性 |
| 翻案风暴(窗口内连续翻案) | 纠正走同一队列, 批量合并; 回放深度 ≤ 窗口 |
| 十判计算积压 | 0.5s 最小间隔节流, 队列清空才重算 |
