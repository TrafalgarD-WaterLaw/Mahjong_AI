# 麻将AI助手 v4 设计方案 — 事件流 + 全局归属解码

日期: 2026-08-14
状态: 设计已确认(用户逐节通过)
范围: 欢乐麻将 PC 客户端(只读辅助)为主, 未来扩展线下真实牌桌

---

## 1. 背景与动机

现行方案(2026-08-14-current-design)的批判揭示了四个结构病根:

1. **开放链无纠错**: 行动者轮转是硬链条(校准→推进→副露转移),纠错点只有"新牌首现"一处;错误自我维持,空间证据恰在交错区(最需要纠错处)最弱
2. **硬观测毒化推断**: 归属 90% 对 → 每 10 张错 1 张,错位事件等权进入粒子滤波
3. **固定框 vs 增长型 UI**: 框选区域随副露组数/牌河行数增长而溢出
4. **回溯 3 帧假设失效**: 检测 recall 74%,漏检可持续几十帧,首现帧行动者不可信

用户决策(2026-08-14): **摒弃现有归属/状态方案,重新设计**,以目标为需求,PC 游戏为主、未来线下扩展。

## 2. 目标与成功标准

- **对手手牌推断**(核心创意): 谁打了什么 → 听牌概率/放铳率
- **我的牌效辅助**: 出牌推荐/听牌提示(只依赖我的手牌,高可靠)
- **成功标准**: 真实对局核对指标 — 四家牌河逐张正确率(人工核对)、终局听牌/放铳命中(settle_check)、归属分布平均熵(自诊断)

## 3. 需求澄清结论(用户确认)

| 决策点 | 结论 |
|---|---|
| 重构范围 | 重建感知+状态层;复用规则引擎/牌效/粒子滤波框架/数据集/模型 |
| 统一程度 | 统一核心+场景适配器;现在只实现 PC 适配器,线下适配器未来加 |
| 归属方案 | A: 事件流 + 滑动窗口全局解码(软归属,回看纠错) |
| 回合指示 | 游戏界面**没有**回合指示 — 行动者只能靠轮转模型/动作轨迹推断 |

## 4. 方案选择

三方案对比:

| | A 全局解码(选中) | B 动作轨迹为主 | C 软归化 |
|---|---|---|---|
| 归属机制 | 窗口联合解码 + 软分布 | 打出动画轨迹起点 | 硬链换贝叶斯软更新 |
| 回看纠错 | ✅ 窗口内反复重解 | ❌ | ❌ |
| 线下前景 | 事件接口天然复用 | 最强(线下主信号) | 弱 |
| 风险 | beam search 复杂度 | PC 动画仅 2-3 帧,漏检率高 | 只治一个病 |

选 A 理由: 同时消灭三大病根;事件日志天然是复盘工具与线下适配器接口;B 的动作证据作为 A 的证据源之一(未来线下升为主信号)。

## 5. 架构总览

```
┌─ 场景适配层(现在只实现 PC) ────────────────────────────┐
│ 捕获 → YOLO 检测 → ByteTrack → ROI 精修 → 聚类(全复用) │
│        ↓ 产出: 观测事件流(场景无关的接口)                 │
├─ 核心层(与场景无关 — 线下复用, 零改动) ─────────────────┤
│ ① 事件提取器   检测帧 → 事件(纯函数)                    │
│ ② 归属解码器   滑动窗口联合解码 → 每家概率分布           │
│ ③ 对局状态     事件日志 = 唯一事实源                     │
│ ④ 推断层       粒子滤波软观测 → 推荐 + 放铳率            │
├─ 展示层 ────────────────────────────────────────────────┤
│ 客户端(事件日志驱动, 无闪烁) + 悬浮框                    │
└─ 验证层: 事件日志 JSONL 本身 = 复盘文件 = 结算核对输入 ───┘
```

**原则**:
1. 核心层只消费"观测事件",不消费像素 — 场景差异封装在适配器
2. 事件单调追加、永不改写 — 事件日志即复盘文件
3. 归属是概率,不是结论 — 推断按分布加权;显示取 MAP

## 6. 观测事件模型(核心接口)

感知层报"发生了什么",不带归属结论:

```python
TileAppeared   # 桌面出现一张新牌(潜在打出)
  tile, track_id, pos, conf, ts, frame,
  motion: MotionEvidence | None   # 打出动画轨迹(起点/方向/置信度), 可选
MeldFormed     # 一组紧贴亮牌出现(碰/杠/吃候选): boxes, cx, cy, ts
TileClaimed    # 刚出现的牌被邻家副露吸收: tile_id, ts
HandChanged    # 我的手牌去抖变化: n_old→n_new, ts(13→14 = 我摸牌)
```

- 提取规则独立可单测(每条规则给检测帧序列,断言输出事件);时间建模(轨迹连续性/确认窗口)由解码器统一承担
- 花牌(tile 34)在提取器分流为亮花事件,不进归属

## 7. 归属解码器(核心算法)

**对象**: 窗口内最近 K 个未冻结的 `TileAppeared` 事件(K≈8-12)。每个事件维持 4 家上的归属分布。

**约束 — 轮转自动机**:
```
状态 = (当前行动者, 本轮各家已打标记)
正常转移: 我→右→上→左 循环, 每家本轮至多打一张
副露截断: MeldFormed 确认 → 自动机跳到该家(碰家接着打)
亮花: 不占名额
HandChanged 13→14: 相位锚定(我摸牌 → 轮到我)
```

**证据模型**(每事件 × 每家的对数得分):
```
score(e, p) = w1·log P(pos | p)      # 空间似然: 在线学习的高斯/直方图
            + w2·log P(motion | p)   # 动作证据: 轨迹起点在 p 手牌区(可选)
            + w3·turn_prior(e, p)    # 轮转自动机当前相位到达 p 的先验
```

**解码**: 事件序列在自动机状态空间上 beam search(束宽 ~16)→ 每事件后验分布。

**关键差异 vs 现行方案**:

| 现行 | 新 |
|---|---|
| 硬区域(固定框)权威归属 | 空间似然(初始用 river_regions 框做种子先验,已冻结事件在线更新 — 溢出问题消失) |
| commit 后不回退 | 窗口内反复重解;**出窗口时冻结** |
| 行动者单点链条 | 自动机整体后验,回看纠错 |
| 副露补全靠启发式 | TileClaimed 显式事件 |

**降级路径**: 空间似然退化宽先验、motion 缺失、轮转先验变平 → 解码器输出高熵分布而非乱猜;开局无历史时窗口短,先冻结空间解,随证据增多自动修正。

**取舍(已确认)**: 出窗口时冻结 — 老事件不再翻账,换来窗口有界、显示稳定。

## 8. 对局状态 + 推断

**状态** = 事件日志投影(纯函数,单测友好):

```
事件日志(唯一事实源, 只增)
  ├─ 各玩家牌河 = 该家已冻结 TileAppeared 事件的牌序(含被碰走的)
  ├─ 显示牌河 = 牌河中"当前物理可见"子集(被 TileClaimed 排除)
  │             → 碰走的牌从显示消失, 推断保留; 事件驱动, 无闪烁
  ├─ 副露集合 = MeldFormed 事件
  └─ 我的手牌 = HandChanged 去抖结果(现行去抖保留)
```

**推断层(复用 + 一处接口升级)**:
- 粒子滤波框架、牌效引擎、放铳率、操作建议 — 全部复用
- 唯一改动: `observe_discard` 接收归属分布(按 P(p|e) 加权更新粒子)— 软观测落地
- 副露扣池: 由 MeldFormed/TileClaimed 事件驱动。正常路径: 被碰走的牌已有 TileAppeared(打出者牌池已扣),副露按亮牌数扣(碰/吃 2, 杠 3);秒碰漏检路径: TileClaimed 指向从未出现的牌 → 该副露扣池数 +1 近似(打出者少记的这张由副露方补扣)

## 9. PC 感知适配层

- **检测 + ByteTrack + ROI 精修**: 原样保留(模型/数据/参数不动)
- **聚类**: 降级为事件提取辅助 — 手牌簇、副露紧凑组检测仍用;牌河归属逻辑全部移除
- **事件提取规则**:
  - 新 track_id 出现且持续 ≥2 帧且位置稳定(相邻帧框中心位移 < 0.5×框宽;初始值, M1 单测标定)→ `TileAppeared`
  - 紧凑亮牌组持续 ≥3 帧 → `MeldFormed`(位置匹配去重)
  - 手牌去抖 n 变化 → `HandChanged`
  - 刚确认的 TileAppeared 落进确认的 MeldFormed → `TileClaimed`
- **动作证据(可选增强)**: 帧差/光流检测打出动画 — 检出就进 evidence 强加权,检不出不影响(证据不是链条)。PC 动画快,预期检出率一般,实验性信号,权重低起步
- **花牌**: 类别 34 → 亮花事件,不产生 TileAppeared

## 10. 验证体系

- **事件日志 = 复盘文件**: `game_*.jsonl` 事件级日志 — 每条含归属分布、冻结决策、证据得分
- **合成事件单测**: 事件流合成器(底牌剧本 + 噪声: 漏事件/假事件/位置扰动)→ 解码器回归测试;窗口 K、束宽、权重的每次调整有硬指标
- **真实对局验收**: 5+ 局 — 人工核对四家牌河逐张正确率(主指标)、settle_check 终局对比、归属分布平均熵(自诊断)
- **复盘工具**: 事件日志 → 对局报告(四家牌河时间线/副露/归属置信度)— 简历展示物 + 验证核心

## 13. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| beam search 复杂度超预算 | 窗口 K 与束宽可调;自动机状态空间天然小;M1 单测量化 |
| 事件漏检(检测 recall 74%) | 漏事件只损失信息不连锁错位;软归属+先验兜底 |
| 空间似然初始种子不准 | 初始用现有框,在线更新逐步修正;熵指标监控 |
| 动作证据在 PC 检出率低 | 权重低起步,作为增量信号;M4 线下才是它的主场 |
| 碰牌秒碰(事件从未出现) | 副露扣池多扣近似;概率化后影响可控 |
| 新旧管道并行维护 | 旧代码冻结不再改(除严重 bug);新代码全在新模块, 客户端只新增入口 |
